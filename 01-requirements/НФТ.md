# Нефункциональные требования и метрики мониторинга функционала продукта Трансграничные переводы

## Описание значимости артефакта

| Раздел | Содержание |
| --- | --- |
| **Процесс и контекст использования** | Этап определения ограничений и стандартов качества системы. Применяется при проектировании архитектуры, выборе инфраструктуры и настройке мониторинга |
| **Цель создания** | Гарантировать, что функционал трансграничных переводов будет работать быстро, надёжно и безопасно |
| **Что становится определено** | Метрики производительности, требования к безопасности, надёжности, масштабируемости, мониторингу и аудиту |
| **Пользователи артефакта** | Архитекторы, DevOps-инженеры, разработчики, QA-инженеры |
| **Использование в дальнейшем** | Настройка алертов в Prometheus/Grafana, проведение нагрузочного тестирования, выбор инфраструктуры, настройка логирования и аудита |
| **Последствия отсутствия** | Невозможность оценить качество реализации, риск выбора неподходящей инфраструктуры, проблемы с безопасностью и соответствием регуляторным требованиям |

## Нефункциональные требования

| № | Категория | Метрика | Описание |
| --- | --- | --- | --- |
| НФТ-1 | **Производительность** | Время ответа API создания перевода | API создания перевода должен отвечать не более чем за 500 мс (p95) и 1000 мс (p99) |
| НФТ-2 | | Время ответа API просмотра истории переводов | Список переводов должен загружаться не более чем за 300 мс (p95) |
| НФТ-3 | | Время обработки вебхука от платёжного шлюза | Вебхук должен обрабатываться не более чем за 200 мс, чтобы шлюз не отправлял повторные запросы |
| НФТ-4 | | Таймаут запроса к сервису комплаенс-проверки | Запрос к внешнему сервису комплаенс-проверки должен завершаться в течение 5 секунд |
| НФТ-5 | | Время установки SSE-соединения | SSE-соединение должно устанавливаться не более чем за 500 мс (p95) |
| НФТ-6 | | Частота обновлений курса через SSE | Курс должен обновляться не чаще одного раза в 30 секунд |
| НФТ-7 | | Время переподключения SSE при обрыве | Переподключение должно происходить в течение 3 секунд |
| НФТ-8 | | Таймаут запроса к FX-сервису | Запрос курса валют должен завершаться в течение 3 секунд |
| НФТ-9 | | Таймаут запроса к Банку-отправителю (холдирование) | Запрос на холдирование средств должен завершаться в течение 10 секунд |
| НФТ-10 | | Пропускная способность системы | Система должна поддерживать не менее 100 RPS (переводов в секунду) |
| НФТ-11 | **Безопасность** | Шифрование данных в покое | Все персональные данные и финансовые операции должны шифроваться алгоритмом AES-256 |
| НФТ-12 | | Шифрование данных при передаче | Все коммуникации должны использовать TLS 1.3 |
| НФТ-13 | | Защита от повторных атак | Использование Idempotency-Key (UUID) для всех финансовых операций |
| НФТ-14 | | Маскирование чувствительных данных | Номера счетов, пароли и персональные данные не должны попадать в логи в открытом виде |
| НФТ-15 | **Надёжность** | Гарантия доставки событий | Гарантия доставки at-least-once через Kafka для событий изменения статусов. Обработка дубликатов через ключ идемпотентности |
| НФТ-16 | | Circuit Breaker для внешних сервисов | При недоступности внешнего сервиса (AML, FX, банк) система переходит в режим Circuit Breaker (таймаут 5 сек, retry 3 попытки) |
| НФТ-17 | | Dead Letter Queue (DLQ) | Все события, не обработанные после 10 попыток, попадают в DLQ для ручного разбора |
| НФТ-18 | **Доступность** | Время доступности системы | Система должна быть доступна 99.9% времени |
| НФТ-19 | | Время восстановления после сбоя (RTO) | Не более 30 минут |
| НФТ-20 | | Потеря данных при сбое (RPO) | 0 минут, потеря зафиксированных транзакций недопустима, обеспечивается WAL-архивированием |
| НФТ-21 | **Масштабируемость** | Одновременные пользователи | Система должна поддерживать до 10 000 одновременных пользователей |
| НФТ-22 | **Мониторинг** | Метрики производительности |Метрики в Prometheus: "latency", "throughput", "error rate" "transfer_creation_time", "transfer_status_change_count", "aml_check_time", "webhook_processing_time", "refund_processing_time" |
| НФТ-23 | | Алерты на критические ошибки | Алерт в Grafana при "error rate" > 5% или "latency P99" > 2000 мс в течение 5 минут |
| НФТ-24 | | Алерты на сбои интеграций | Алерт при 3 и более последовательных ошибках интеграции с AML, Банком или шлюзом за 5 минут |
| НФТ-25 | **Аудит** | Логирование финансовых операций | Каждая операция создаёт лог с user_id, timestamp,transfer_id, статусом |
| НФТ-26 | | Неизменяемость аудиторских логов | WORM-хранилище (Write Once Read Many) для логов финансовых операций |
| НФТ-27 | | Срок хранения аудиторских логов | 5 лет (требование ЦБ РФ и 152-ФЗ) |
| НФТ-28 | **Совместимость** | Формат данных API | JSON для запросов/ответов, ISO 8601 для дат, ISO 4217 для валют |
